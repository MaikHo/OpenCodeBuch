# 21. Working with Knowledge Sources in a Controlled Way

The same basic idea does not apply only to source code.

Large documentation sources should not simply be dumped into the context and "summarized" in one pass either.

## Three phases

I like to separate this kind of work into:

```text
Source Intake
→ ingest and structure the source

Topic Synthesis
→ process exactly one topic from relevant sources

Source Finalization
→ document successful processing and close the source
```

The template contains neutral workflow examples for this.

## Ingest the source

First, metadata and structure are determined.

A script can, for example, identify pages, sections or file types.

The model only receives the information it needs to plan the processing.

## One topic instead of an entire collection

Afterwards, not "everything" is processed at once.

For one topic, only the relevant sections are loaded.

That reduces context and makes contradictions visible.

## Contradictions stay contradictions

If two sources contain different statements, the model does not decide by itself which one sounds more convenient.

The conflict is documented.

It is the same principle as with architecture knowledge:

```text
Unknown stays Unknown.
Conflict stays Conflict.
```

## Finalization only at the end

A source is marked as processed or archived only after the corresponding processing step has genuinely been completed.

That keeps the documentation workflow traceable and resumable as well.
