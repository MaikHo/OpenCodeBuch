# Spec Backlog

Hier liegen gespeicherte Specs, die noch nicht als aktive Umsetzung freigegeben wurden.

Eine Spec beschreibt **Was und Warum**, nicht die technische Lösung.

Empfohlenes Format:

```markdown
# Spec — <Titel>

**ID:** 0012
**Status:** Backlog

## Ziel
## Nicht-Ziele
## Ist-Zustand
## Soll-Verhalten
## Randbedingungen
## Akzeptanzkriterien
## Risiken
## Offene Fragen
```

Eine Backlog-Spec allein autorisiert weder Planung noch Implementierung. Im bereits ausdrücklich gestarteten `/create-spec-to-plan` erlaubt `Spec übernehmen` nur, aus genau dieser Spec anschließend einen **Plan-Vorschlag** zu erzeugen. Implementierung bleibt weiterhin gesperrt.
